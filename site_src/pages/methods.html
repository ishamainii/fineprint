Data

Open Terms Archive tracks platform documents and commits a new version to a public git repository whenever the text changes1. I walked the history of every privacy policy and terms of service for 26 tracked services, 2,283 versions from July 2022 to November 2026, with a small Python script that reads each version straight out of git into SQLite, and split each version into sentences. Two of the services are the same product before and after a rename, so I merged them, which leaves 25 platforms.

The archive also commits when it changes how it collects a page, not just when the page changes. Those 78 maintenance commits stay in the data but are never counted as a revision.

Making search fast

Every question in this project starts as a search: which sentences mention X? Scanning all sentences with a regular expression took two to three seconds a query, and a SQL LIKE scan still had to read every row. I built a full-text index with SQLite FTS5, an inverted index that maps each word to the rows containing it, in 3.3 seconds. After that, the same queries return the same results in a few milliseconds. That's what made it practical to test hundreds of phrasings while building the classifier.

Finding the clauses

The 12,834 sentences that mention AI across all versions are only 355 distinct sentences, because unchanged text repeats from version to version. I hand-labelled a stratified sample of 133: all the keyword-rule hits, plus hard cases that talk about data, models or improvement without the word "train," plus a random set of other AI sentences. The question for each was: does this say people's data is used to train, develop or improve AI or machine-learning models (including the legal basis or opt-out for doing so)?

The keyword rule (an AI term and "train" or "fine-tune" in one sentence) scores precision 0.86, recall 0.69, F1 0.77 against those labels. The TF-IDF and logistic-regression classifier, trained on the same sentences with company and product names replaced, scores F1 0.89 ± 0.01 across ten repeats of 5-fold cross-validation, raising recall from 0.69 to 0.89. A sentence counts as a training clause in this project if my label says so, or, for unlabelled sentences, if the classifier and the keyword rule agree.

Measures

In force: for quarterly figures I use only the latest version of each document as of the last day of the quarter. Reading ease: Flesch reading ease with a simple syllable counter, on sentences of 5 to 80 words, so flattened tables don't distort it. Hedging: a fixed list of words and phrases, counted per 100 words. Similarity: cosine similarity of TF-IDF vectors (words and word pairs). Revisions: the sentences in a version that weren't in the previous one, plus those that disappeared. Distinctive words use the log-odds method with an informative Dirichlet prior2.

Limits

This is two document types for 25 platforms, and some companies explain AI training on separate help pages that aren't tracked, so "no clause found" means none in these documents. Dates are when the archive first saved the wording, which can lag the real change by days, and for one platform the clause was already present on the first day of tracking. The labels are mine and are published with the code, so anyone can disagree with them and re-run everything. Platforms are anonymised in this write-up, but the source data is public.

Code

Everything is in github.com/ishamainii/fineprint: the extraction, search benchmark, classifier, analysis and this site, with instructions to rebuild it from scratch. Python (pandas, scikit-learn, SQLite FTS5) for the analysis, plain JavaScript and SVG for the site.
